# 本地虚构秘密材料服务

这是一个纯本地 Go 服务包，用来给后续示例应用管理虚构秘密材料的版本、短期借用与轮换。

## 当前能力

- 材料经 AES-256-GCM 加密后保存在 `secret-materials.json`。
- 借用凭据保存有效期和 SHA-256 令牌哈希；原始令牌只在签发时返回，文件位置为 `lease-credentials.json`。
- 使用记录单独追加到 `usage-audit.jsonl`，只记录材料名、版本、借用 ID、主密钥 ID、动作、结果和原因。
- 借用到期、撤销后均无法继续取出材料；重复撤销保持幂等。
- 借用必须声明用途与访问范围；范围外的读取、审计等操作会被拒绝。每份借用固定在签发时的版本，不能借一个用途去读另一版本。
- 借用可再次委托给临时使用者；下游用途必须位于上游用途层级内，操作范围、材料版本访问和期限只能是上游许可的子集。
- 任何一级借用被撤销后，其全部下游借用会同步失去能力；上游到期时，下游即使自身尚未到期也不能继续操作。
- 轮换期间分别追踪固定旧版本和明确允许采用新版本的借用；只有整条上游链都允许新版本时才会采用新版本，轮换本身不会扩大委托权限。
- 委托、上游到期、上游撤销和操作请求的决定会写入审计；审计只包含借用 ID、用途决定和版本 ID，不包含材料内容或原始令牌。
- 轮换后的新借用自动指向新版本；旧借用支持 `until_expiry` 或 `grace_period` 两种声明式收尾规则。
- 轮换后可用有界批次逐批结束旧版本借用；撤销是终态，批处理或状态恢复都不能让借用重新可用。
- 进程重启会保留加密材料、借用和审计，但解密只在仍持有同一把进程内主密钥时有效。
- `UseWithReceipt` 在一次被允许的使用后签发使用回执：回执只含材料版本、用途哈希（可选披露前缀）、最终决定和逐层委托哈希链，不含材料正文。
- 每次签发同时把这次使用登记为不可自造的授权事实（`ReceiptRecord`）：服务端快照精确钉住使用对象（材料与版本摘要）、用途提示、最终决定、完整委托链上每一层的身份与链接哈希。回执不是自证文件，换材料版本、换摘要并重算回执哈希会因与登记的使用事件不符而被判为 `invalid`；固定旧版本的借用也无法借此冒充新版本使用。
- 回执可离线核对：`VerifyReceipt` 只需回执和核验者明确持有的授权事实（`authorization-facts.json`），不需要服务、主密钥或网络。核验结论分三态：`valid`（事实证实同一次使用确已发生且当时允许）、`invalid`（所持事实与回执矛盾，如篡改、换版本或跨回执拼接）、`undetermined`（缺少登记事件、必要委托或版本等依据；既不冒充非法也不冒充当前可用）。
- 删去任意一层委托、替换使用对象或叶子借用、改动决定、把其他回执的链接或并行委托链接进本回执，都会使核对失败；多条各自合法却互不相容的授权路径不能合成一次更宽的许可。
- `RedactFactsForReceipt` 生成交给无材料正文核验者的最小事实子集：只含本次使用事件、所需的委托层（用途以哈希表示）和用到的单个版本摘要，不含无关授权与业务正文；部分披露下由签发时登记的用途包含见证（仅哈希）确认下游用途位于上游用途之内。
- 核对结果区分"当时合法"（`Valid`/`status=valid`）与"现在仍可用"（`CurrentlyUsable`）：事后上游撤销或到期不会让旧回执失效，但会标记当前不可用。
- 回执中的 `PurposeHint` 是可隐藏的业务说明而非使用事实：持证人可在出示前清空或缩短它，离线核验仍判 `valid`；但提示只能是签发时登记提示的前缀，替换、扩写或从其他回执拼接提示都会被判 `invalid`。材料版本、用途承诺（哈希）、最终决定与委托链始终钉死，不随提示隐藏而改变。
- 授权事实随借用、委托、轮换、撤销和回执签发自动持久化，重开进程后回执依赖的事实仍可追溯；事实文件只存密文摘要，不写材料正文。
- `VerificationTask` 是可保存的离线核验任务：一次登记多份历史回执，逐批补交授权事实与发生记录（可乱序、可不完整）。每次核验为每份回执追加一条只增不改的决定，记录结论、所依据的事实批次（`BasisBatches`）与仍缺少的材料（`Missing`）；补充材料只产生新决定，先前的无法确定或拒绝结论保留在历史中不被改写。同一回执重复到达只计一次使用，同一材料版本的不同回执分别计数；事实批次相互矛盾时，受影响回执标为 `conflict` 并列出冲突依据批次，其他回执继续核验。任务可 `Save`/`LoadVerificationTask` 持久化，重开后继续核验。
- `Export` 生成只含所需事实的离线核验包（`VerificationPackage`）：用途仅以哈希出现，不含无关授权与材料正文；接收者用 `Reproduce` 即可复现选定决定，导出本身不改变原任务。

## 主密钥边界

演示主密钥通过 `GenerateDemoMasterKey()` 在进程启动时临时生成，不会写入材料文件、凭据文件或审计日志。

如果进程重启并生成新的主密钥：

- 旧版本仍保留在磁盘上，但调用 `Use` 会得到包含 `ErrMaterialCannotDecrypt` 的错误。
- 可以轮换材料并继续签发新版本借用。
- 旧版本不会也不能被新主密钥“恢复”解密。
- 真实用户密钥、外部 KMS 密钥或任何生产密钥材料都不参与本演示。

## 快速验证

```bash
go test ./...
go vet ./...
```

最小接入方式见 `cmd/demo/main.go`。三个数据文件有意分开，删除或替换其中一个时可以分别观察材料、凭据和审计边界。

```bash
go run ./cmd/demo -dir /tmp/local-materials-demo
```

回执演示（并行授权、上游轮换、回执篡改，全程不输出材料正文）：

```bash
go run ./cmd/receipt-demo -dir /tmp/local-materials-receipt-demo
```

核验任务演示（乱序补交、提示隐藏、事后撤销、任务重开与导出复现）：

```bash
go run ./cmd/verify-task-demo -dir /tmp/local-materials-verify-task-demo
```
